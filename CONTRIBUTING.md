# Contributing

Start with [DEVELOPMENT.md](DEVELOPMENT.md) and [ROADMAP.md](ROADMAP.md). Small, reproducible changes are welcome: controller UX, protocol tests, hardware findings, memory/performance analysis, documentation, and the next looper/phone milestones.

- Describe the problem and expected behavior. Include your exact app and firmware versions.
- Run the relevant offline tests. Say explicitly whether hardware was used.
- Preserve flash bounds, image hashes, silence guards, and upstream attribution.
- Do not commit stock firmware, downloaded captures, device backups, login tokens, serial numbers, or local account data.
- Treat a new firmware image as experimental until tested on hardware. Never describe an emulator result as a physical recovery or timing guarantee.
- Submit original changes under the MIT license; third-party contributions must retain their original notices.

The source tree contains historical research paths. A successful host build does not mean every historical experiment or independent backend is ready for a device.
