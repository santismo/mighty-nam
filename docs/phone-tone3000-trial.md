# TONE3000 phone controller trial

Controller **0.6.0** is published at https://santismo.github.io/nam-plug-controller/?v=0.6.0 (commit `5fb2434f0cedf08e64cc657b17251201fb5a6d85`). It uses the existing **NAMLNK14** RAM model protocol. No firmware change, physical preset write, host audio stream or system audio setting change was made for this release.

## Using it

In Bluefy, open **Captures → Browse TONE3000**. The official catalog handles sign-in, full search and filters. Choose a tone with **Select Tone**, then **Load capture** on its model. The browser validates and extracts the compatible 48 kHz A2 Lite model, including Lite inside a combined A2 file. Returning from TONE3000 closes Bluetooth; tap Connect to load the selected download in normal mode.

After acknowledged chunks, commit checksum and status readback, the downloaded model becomes active. Output stays muted. Amp + cabinet captures bypass the stock cabinet. Phone favorites are independent, and multiple captures can be favorited. **Save to plug** explicitly chooses one of seven colors and stores capture, chain, buffer, name and FX A/B. A changed destination is rejected before saving. The save dialog preserves an existing color’s power-on output preference and lets the user change it. Saving itself remains muted.

A2 Lite is the current fixed topology; this release does not run arbitrary A1, other A2 sizes, or non-48-kHz captures. A downloaded capture is never labeled active before the device confirms it. Transfers never write firmware. Failed transfers are not automatically retried; a subsequent explicit load can abort this browser’s exact unfinished session on the same device. Preset saves are never retried automatically.

## Validation and remaining check

All **63 Node tests** passed. Tests include malformed models, CRC/session mismatch, cancellation, lost replies, preset switching, interruption recovery, exact capture save/readback, unrelated preset preservation, PKCE state/replay/expiry, token origin restrictions and single-flight refresh.

The exact NAMLNK14 ARM image accepted all 35 model messages generated by the JavaScript controller through its Bluetooth-channel parser, with split frames and byte-ring wrap. Its replies passed the JavaScript parser. The Fender slot matched the established Mac/Python transfer byte for byte. The emulated DMA stayed silent and there were no flash writes. These are protocol/emulation checks, not measurements of the physical BLE radio.

Real browser sign-in, profile/library reads, Fender selection, model download, strict extraction, caching and favoriting were verified. Downloads require following the official storage redirect; only the model-download route follows redirects, and CSP limits network destinations to TONE3000’s API origins. Browser Fetch strips the Authorization header when the redirect crosses origins. Tokens stay in memory; only short-lived PKCE state, local captures and recovery identifiers are stored locally. No tokens or captures are in this repository or the public controller repository.

The published page and nine checked assets match local SHA-256 hashes. The Mac did not see a NUX/Mighty USB device during the final read-only inventory check. **The user deferred the first end-to-end Bluefy → physical plug model transfer.** Do that with headphones unplugged, verify the selected capture becomes active and remains muted, then optionally save to a chosen color and check it after restart. Do not describe physical Bluetooth loading as confirmed until that trial succeeds.

The phone integration uses the free official picker and bounded library feeds described in [TONE3000’s API documentation](https://www.tone3000.com/api) and [terms](https://www.tone3000.com/api/terms). This implementation review is not a legal opinion on the separate Mac app, firmware or distribution rights.
