01 / SOURCE

A project you can inspect.

The Flutter controller, native MIDI bridge, compact A2 Lite engine, firmware hooks, tests, and protocol notes are public. Original work is MIT licensed by santismo; upstream licenses stay with their code.

The current working route is a stock-based hybrid. It preserves stock audio drivers and effects while replacing amp processing with NAM. The independent startup/audio backend is research, not a finished replacement firmware.

02 / MAC APP

Build the controller.

The reference build uses Flutter 3.27.4 / Dart 3.6.2, Xcode tools, and CocoaPods.

cd app
flutter pub get
flutter test test/nam
flutter build macos --release \
  --dart-define-from-file=config/tone3000.json

Forks should register their own TONE3000 public application ID. Never embed account tokens or client secrets. The shipped app’s sign-in session is stored in Keychain.

03 / FIRMWARE

Build locally. Preserve the checks.

Use the supplied toolchain requirements and build flags to compile NAMLNK10. Packaging requires your own exact MP3 V1.5.6 Original(VT) package, an ELF matching the recorded validation evidence, and the bounded memory/storage checks.

The packager generates a local candidate; it does not flash the device. The checks reject mismatched firmware, changed source evidence, unexpected memory changes, and invalid images. Changed code needs new evidence.

Candidate construction steps and exact hashes ↗

Source availability is not hardware validation.

Some historical research scripts require local stock payloads, previous lab reports, or privately licensed model inputs. Recorded evidence is published with its scope; it is not a promise that every historical experiment runs from a fresh checkout without additional inputs.

04 / ARCHITECTURE

Three layers, one guitar path.

01

Mac controller

TONE3000 sign-in, favorites, chain editing, seven color drafts.

02

USB control

Bounded MIDI SysEx commands, model validation, metadata readback.

03

On the plug

A2 Lite + stock effects, guarded output, experimental flash preset bank.

Bank records contain a model, effect settings, chain order, name, and buffer choice. Two copies per slot, CRCs, and a final commit marker allow the offline tests to recover a complete prior record after interrupted writes.

05 / CONTRIBUTE

Build the next useful thing.

The next goals are a standalone threshold-triggered looper and iPhone control. Memory ownership, real-time headroom, and phone transport experiments are valuable contributions.

Include a clear reproducer and relevant tests. Distinguish physical measurements from emulator results. Preserve licenses and safety checks; keep proprietary images, personal captures, and credentials out of commits.
